# Implementation Status

최신 갱신: 2026-09-29. 이전 날짜의 검증 결과는 당시 기록이며 아래 최신 섹션을 우선한다. [내부망 설치 및 사내 API 계약](intranet-deployment.md)을 운영 설정의 기준으로 사용한다.

## 2026-09-29 디자인 시안과 대화방 일정 적용

- 기존 레이아웃과 창 크기를 유지하고 Messenger 로고 글자를 15px로 축소, 보조 문구 제거. 상대방 말풍선은 흰 바탕·회색 테두리·검정 글씨, 내 말풍선은 연한 파랑으로 적용. 답장 인용 글씨도 대비 조정.
- 사용자 목록 화면에 이름/아이디/부서 검색, 부서 필터, 접속 상태, 1:1 대화 시작 연결.
- 대화방 헤더의 일정 버튼, 가까운 일정 요약, 우측 일정 패널, 등록·수정·취소 창 추가. 시작/종료 일시, 여러 날짜에 걸친 일정, 장소 없음/있음, 7층·8층 중 회의실 선택 지원. 장소 없음으로 전환하면 기존 장소 제거.
- 알림은 시작 시각 또는 5/10/30/60분 전, 공개 및 알림 대상은 대화방 전체/나만 선택. 전체 대상은 등록·수정 시점의 참여자이며 나중에 참여한 사람에게 기존 알림을 소급 생성하지 않는다. 회의실 예약·중복 예약 방지 시스템과의 연동은 포함하지 않는다.
- Flyway V7에 일정·개인별 알림 저장. 인증된 현 참여자만 조회, 등록자만 수정·취소, 나만 일정은 다른 참여자에게 비공개. revision 검사로 오래된 수정/취소 방지. 변경 시 이전 알림 교체·삭제, 퇴장자 알림 접근 차단. 클라이언트 사이의 시간대 차이를 피하도록 epoch milliseconds 저장.
- 실행 중 5초 간격으로 서버 시간 기준 도래 알림 확인. 최소화 중에도 데스크톱 팝업 표시, 클릭 시 해당 대화방 열기. 앱 내 알림에서 5분 뒤 다시 알림/확인/대화방 열기 지원. 확인하지 않은 알림과 다시 알림 시각은 서버에 남아 재접속 후 조회한다. 앱 종료·기기 절전·네트워크 단절 중에는 팝업을 띄우지 않으며 재접속 뒤 표시한다.
- 적용: 백엔드를 재시작하면 기본 개발/운영 설정의 Flyway가 V7을 적용한다. Electron은 다시 빌드한 앱으로 재실행해야 한다. 데스크톱 및 웹 빌드 산출물 갱신 완료; 운영 배포는 수행하지 않았다.
- 검증: 전체 백엔드 87개 중 85개 통과, Redis 연결이 필요한 기존 2개 스킵. 새 일정 통합 테스트 5개는 H2 MySQL 모드에서 실제 Flyway V1–V7 실행 후 저장·권한·검증·수정·취소·알림 재조회·다시 알림 확인. 기존 메시지/답장/공감/파일 업로드 Electron 회귀 검사 통과. 최소화 중 일정 팝업 표시 및 채널 전달 검사 통과.
- UI 검사: 실제 React 화면과 API fixture로 1440×920 및 1100×720 레이아웃, 사용자 필터, 일정 등록·시간 오류·장소 해제·수정·취소·알림 동작 확인. 스크린샷은 `docs/previews/messenger-*.png`이며 테스트용 사용자와 일정을 표시한다.
- 재현: `cd backend && ./mvnw test`; `cd electron-app && npm run test:desktop`; `npm run test:notifications`; `npm run test:schedules`. 일정 UI 검사는 Playwright가 필요하며 외부 설치를 사용하는 경우 `PLAYWRIGHT_PATH`(패키지 경로), `CHROME_PATH`(Chromium 실행 파일)를 지정할 수 있다.

## 2026-09-24 파일 업로드 진행률

- 첨부 파일별 실제 업로드 진행률 막대·퍼센트와 전송한 용량/전체 용량을 표시한다. multipart 전송 비율을 파일 크기에 맞춰 환산한다.
- 파일 전송 100% 이후 서버의 파일 처리와 메시지 저장 대기를 별도 상태로 표시하고, 메시지 저장 확인 후 진행률 카드를 제거한다.
- 업로드 실패 후 재시도는 0%부터 다시 진행한다. 파일 업로드 후 메시지 전송만 실패한 경우 저장된 파일과 재시도 ID를 유지해 재업로드하지 않는다.
- 검증: 타입 검사, 데스크톱·웹 빌드, Electron에서 실제 16MB multipart 요청을 천천히 수신하는 테스트로 중간 진행률·용량·처리 단계·실패 및 재시도 확인. 기존 공감·답장 회귀 검사도 통과.

## 2026-09-24 입력 지연 개선

- 글자마다 전체 대화 목록의 시간·공감·인용·첨부를 다시 계산하던 경로를 분리했다. `ChatMessages`를 메모화하고 이벤트 핸들러를 안정화해 입력·업로드 진행 갱신에서는 변경 없는 목록을 재사용한다.
- 날짜·시간 `Intl.DateTimeFormat` 인스턴스와 사용자 ID 조회 Map을 재사용한다. 메시지나 읽음·공감·삭제·원문 상태 변경 시에는 목록을 정상 갱신한다.
- 동일한 로컬 Electron 빌드 조건의 메시지 1,000개·52회 합성 입력 비교: 입력부터 다음 프레임까지 중앙값 36.2→16.7ms, p95 52.9→17.6ms. 입력 내용·커서·포커스 유지 확인. 수치는 해당 장치의 측정값이며 OS 한글 입력기 자체의 지연을 측정하는 검사는 아니다.
- 재현 명령: `cd electron-app && npm run test:typing`.
- 타입 검사·데스크톱/웹 빌드와 기존 Electron 공감·답장·원문 이동·초안·첨부 진행률/재시도 회귀 검사 통과. 공개 웹의 최신 번들과 데스크톱 재실행으로 적용.

## 2026-09-23 메시지 공감·답장

- 말풍선 아래 공감 선택창과 인원 표시 개선. 선택 변경·취소, 참여자 이름, Esc·바깥 클릭 닫기 지원.
- 텍스트·사진·파일에 원문 인용 답장 추가. 입력창 미리보기·취소, 채팅방별 초안, 전송 실패 시 재시도 ID와 업로드 유지.
- 인용을 클릭하면 이전 페이지까지 조회해 원문으로 이동하고 잠시 강조. 삭제된 원문·인용과 전송 중 원문 삭제 처리.
- 서버에서 같은 방의 원문과 접근 권한을 검증하고 영구 읽음·실시간 응답에 연결. 원문 인용은 일괄 조회하며, Flyway V6에 nullable 원문 ID와 외래 키·인덱스 추가.
- 검증: 프런트엔드 타입 검사·빌드, 전체 백엔드 82개(격리 Redis, 실패·스킵 0), 격리 MySQL 8.0에서 Flyway V1–V6 및 메시지 상호작용 17개, 실제 STOMP 답장 전달, Electron `file://` 화면 자동 검증 통과.
- Electron 검증에는 공감 추가·변경·취소, 이전 페이지 원문 이동·강조, 방별 초안, 텍스트·파일 답장 재시도, 인용 취소 후 입력 유지, 원문 삭제 시 인용 갱신과 전송 차단을 포함한다.
- 적용 시 백엔드와 데스크톱을 새 빌드로 실행한다. 백엔드 시작 시 Flyway가 V6를 적용한다.

- Electron 메인 프로세스 인증과 HttpOnly Refresh 쿠키 유지, 로그아웃/중복 로그인 시 실시간 소켓 차단, 세션 변경 시 캐시 정리
- 사용자 디렉터리·부서 정렬·Presence, DM 중복 방지 키 및 새 채널 최초 메시지 수신
- 그룹 생성/초대/강퇴/자진 퇴장 API와 화면, 방장 권한 검사 및 방장 퇴장 시 권한 이전
- 메시지 저장 확인 후 입력 초기화, 재시도 ID로 중복 저장 방지, 4,000자 제한, 본인 메시지 수정/삭제 API와 화면
