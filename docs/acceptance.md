# Acceptance

## Goal

작업이 끝났는지 판단하는 기준을 기능별로 정리한다.

## Global Done Criteria

- 변경 범위가 문서화된 요구사항과 일치한다.
- 기존 아키텍처 규칙과 보안 규칙을 깨지 않는다.
- 타입, 빌드, 테스트 또는 해당 범위의 검증 결과가 설명 가능하다.
- 실패 케이스에 대한 동작이 명확하다.

## Authentication

- 올바른 사내 계정으로 로그인할 수 있다.
- 잘못된 자격 증명은 적절한 에러로 처리된다.
- Refresh Token 기반 재인증이 동작한다.
- 중복 로그인 시 기존 세션이 만료되고 사용자에게 반영된다.

## Chat

- 채널 목록과 메시지 목록이 조회된다.
- 메시지 전송 후 본인과 상대방 화면에 반영된다.
- 타이핑 상태가 필요한 범위에서 표시된다.
- 많은 대화 이력이 열린 상태에서도 연속 입력의 글자·커서·포커스가 유지된다. `npm run test:typing`은 격리된 Electron 화면에서 메시지 1,000개와 52회 입력을 사용해 입력부터 다음 프레임까지 p95 50ms 미만을 확인한다.
- 읽음 처리와 안읽은 메시지 수가 일관되게 갱신된다.
- 공감 선택·변경·취소와 반응 인원 표시가 동작하고 키보드 및 바깥 클릭으로 선택창을 닫을 수 있다.
- 답장 원문이 입력창과 전송된 메시지에 표시되고, 취소 시 작성한 내용이 유지된다.
- 대화방별 답장 초안과 실패한 전송의 재시도 ID가 유지된다.
- 아직 불러오지 않은 원문도 인용을 누르면 이전 이력을 조회한 뒤 이동·강조한다.
- 삭제된 원문은 인용에도 삭제 상태로 표시되며, 다른 방·삭제된 메시지에 대한 새 답장은 서버가 거부한다.

## File

- 허용된 파일 형식과 크기 내에서 업로드 가능하다.
- 인증 사용자만 다운로드 가능하다.
- 이미지 첨부는 가능한 경우 미리보기 된다.
- 파일 업로드마다 실제 전송 이벤트에 따라 진행률과 용량이 표시된다.
- 전송량 100% 이후 파일 처리·메시지 전송 상태를 구분하고, 실패 시 진행률과 오류를 유지한다.
- 업로드 실패 재시도는 0%부터 시작하며, 메시지 전송만 실패한 경우 파일을 중복 업로드하지 않는다.

## Notifications And Presence

- 사용자 상태 조회가 가능하다.
- 네이티브 알림과 앱 내 알림 목록이 동작한다.
- 미읽음 배지와 트레이 상태가 주요 이벤트에 따라 갱신된다.

## Internal Integrations

- 내부 API 키가 없거나 잘못되면 요청이 거부된다.
- 전체 공지는 저장과 브로드캐스트가 함께 처리된다.
- 특정 사용자 알림은 온라인과 오프라인 케이스 모두 처리된다.

## Documentation

- 새로 추가된 기능이나 규칙은 관련 `docs/` 파일에 반영된다.
- 마스터 프롬프트는 장기 명세를 중복 작성하지 않고 `docs/`를 참조한다.
